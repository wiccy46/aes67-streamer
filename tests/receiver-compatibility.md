# Receiver Compatibility Matrix

Use this matrix before a public release to record whether common AES67/RTP
tools can receive, inspect, or discover a single AES67 stream from this project.

The automated CI path remains `scripts/e2e_loopback.sh`. The multicast and
professional-tool checks below are intentionally manual or opt-in because they
depend on host networking, installed applications, and external hardware.

## Test Stream

Recommended baseline stream:

```bash
AES67_E2E_INTERFACE=<local-ip> \
AES67_E2E_ADDRESS=239.69.67.67 \
AES67_E2E_PORT=55004 \
bash scripts/e2e_multicast.sh
```

Expected media and transport:

| Field | Expected value |
| --- | --- |
| Audio codec | L24 |
| Sample rate | 48000 Hz |
| Channels | 2 for generated test media |
| Packet time | 1 ms |
| RTP payload type | 97 |
| RTP DSCP | 34 / AF41 |
| PTP DSCP | 46 / EF |
| SAP DSCP | 24 / CS3 |
| SAP | Enabled by default |
| PTP clock | External grandmaster if present; otherwise local master fallback |

## Compatibility Checks

| Tool | Mode | Pass criteria | Notes |
| --- | --- | --- | --- |
| ffmpeg / ffprobe | Automated local or multicast RTP receive | `scripts/e2e_loopback.sh` passes in CI; `scripts/e2e_multicast.sh` passes on a multicast-capable interface | ffmpeg receives RTP from generated SDP and validates recorded WAV rate, channels, duration, frames, and non-silence. |
| VLC | Manual SDP receive | VLC opens the SDP, receives the stream, and reports L24/48000/stereo without underrun or decode errors during a bounded run | Use the SDP printed by the streamer or the SDP generated by the multicast script. |
| RAVENNA Stream Monitor | Manual SAP/RTP/PTP inspect | Stream appears via SAP or manual SDP, RTP sequence increases, payload type and packet time match, and PTP reference identity is visible | Record whether the tool sees external PTP or local master fallback. |
| Dante Controller / Dante AES67 mode | Manual AES67 interop | Device can see or manually subscribe to the AES67 stream and reports matching rate/channels | Requires Dante AES67 mode and network setup outside this repo. |
| Wireshark | Manual packet capture | RTP packets decode as L24, RTP DSCP is AF41, PTP packets use EF, SAP packets use CS3, RTP timestamp increments match packet time | Capture with `udp.port == 55004 || ptp || sap` or the selected RTP port. |

## Recording Results

For each release candidate, record:

- Git commit and build profile.
- OS and network interface.
- Stream address, port, payload type, and PTP domain.
- Whether a PTP grandmaster was present.
- Which tools passed, failed, or were not available.
- Relevant logs, screenshots, packet captures, or SDP files.

Do not treat unavailable proprietary tools as automated blockers. For a first
public release, the minimum receiver proof is:

- CI loopback passes.
- Optional multicast script passes on at least one multicast-capable interface.
- Wireshark or equivalent packet capture confirms RTP/PTP/SAP markings.
- At least one common desktop receiver, such as ffmpeg or VLC, receives audio
  from the generated SDP.
